= UniConfig Config Panel
:description: Schema-driven settings UI for config files — ConfigUI app plus UniConfig engine.
:navtitle: Introduction

**ConfigUI** (binary `uniconfig`) opens ordinary config files — INI, YAML, TOML, SDLang, JSON, `tfvars` — and shows the same settings widgets every time: labels, enums, toggles, descriptions, and **fields the author never wrote**.

The reusable engine is link:https://github.com/dev-centr/uniconfig-core[uniconfig-core] (UniConfig). DevCentr and third-party apps depend on the engine without pulling a GUI.

image::layers.svg[alt="Engine, vocabulary, form binder, ConfigUI shell"]

== How vocabulary works

Syntax parsers live in the engine. **Semantic vocabulary** (which fields exist) ships with **your app**:

. Add `uniconfig/catalog.sdl` + JSON Schema beside your product.
. Call `registerCatalogSource` on startup — writes a pointer in `%LOCALAPPDATA%\UniConfig\catalog-index.sdl`.
. ConfigUI lazy-loads that catalog when a matching file opens.

See xref:howto-ship-vocabulary.adoc[Ship vocabulary with your app]. You do not open PRs to UniConfig for normal app settings.

Bundled `profiles/` beside the executable is a **fallback pack** for Git, DUB, Terraform, and similar tools that never ship their own catalog.

[source,powershell]
----
uniconfig .\fixtures\sample.gitconfig
uniconfig register-catalog --id com.example.app --catalog .\uniconfig\catalog.sdl --repository https://github.com/example/app
uniconfig dump .\fixtures\sample.gitconfig
----
